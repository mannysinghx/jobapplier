Research for the five job sites was done 2026-09-24 against their current terms and developer pages (sources are linked in `config/sources.yaml`). Unverified points: the ZipRecruiter MCP terms for custom clients, and the Indeed Publisher API shutdown date (secondary sources only).

### Consequence
No candidate-side submission route is currently permitted on **any** source, including all five major job sites, each of which explicitly prohibits automated applying. So **every application goes through a handoff packet**: you apply on the site yourself. The submission gate, idempotency, limits, challenge handling and kill switch are implemented and tested against a test-only adapter. They take effect when a route is verified.

## Review checklist (for each new source)
1. Link the **current** API docs and terms. Quote the sentence that permits the intended use (`read_basis`, `submit_basis`).
2. Note authentication, rate limits, caching/attribution rules and any geographic restrictions.
3. Confirm that automated candidate submission is **explicitly** permitted, not just technically possible. If it is not explicit, set `submit_permitted: false`.
4. Set `date_checked`. Connectors refuse to run 90 days later until re-reviewed.
5. Implement the connector (fetch + normalize only) with respx-mocked tests. Do not label it supported until tests pass.
6. Add a row to this matrix and an entry to `docs/OPS_LOG.md` when it is enabled in production.
